Voice to voice · multi-agent · product discovery

How a spoken question becomes a grounded, cited answer

ShopVoice listens, plans, pulls evidence from a private product catalog (and the live web when asked) through MCP tools, checks its own answer, and speaks a recommendation of at most 15 seconds while the screen shows the comparison table, the citations and the full trace. The workflow is orchestrated with LangGraph.

3Who decides what: the LLM judges, code guarantees

The design rule: anything that must not go wrong (budget, citations, tool allow-list, safety refusals) is not left to a prompt but enforced in code. The LLM does the parts that need language understanding, and every LLM node has a fallback that needs no model.

NodeThe LLM decidesCode guaranteesPrompt
Routertask, budget, brand, material, named products, whether live info is wantedharm and chemical-mixing inputs are blocked before any model call; a spoken budget is never lost; quoted “SYSTEM:” text cannot change constraintsrouter.md
Plannerquery wording, ranking criteriaalways one catalog step; web.search only when live info was asked; budget and brand copied into filters; at most 4 stepsplanner.md
Retrieverwhich tool calls to issue, whether to retry with a simpler querytool allow-list; hard constraints re-applied to every call; tool text sanitised; named products looked up without the budget filter; live and catalog prices reconciledretriever.md

4Agentic RAG: how a product is found

Vector search always returns its nearest neighbours, so the hard part is not finding something but deciding whether it is what the user asked for.

① Metadata filtersprice range, brand, category, rating, applied to both retrievers
→
② Dense + sparseChroma cosine similarity; BM25 keywords
→
③ Fuse and rerankreciprocal rank fusion, reranked by title coverage
→
④ Relevance labelstrong / weak: only strong hits become evidence
→
⑤ Type, material, named checksa “wooden maraca” is not a “wooden puzzle”
→
⑥ Reconcile with livematch by ASIN, then title; a gap above 10% is a conflict

Self-correction

No strong hit: retry with a simpler query. A rating filter that cannot be met (the dataset has no ratings) is dropped, and the answer says so.

Conflicts are shown

The catalog price is a January 2020 snapshot; the live price is newer. When they differ both are reported with their sources, and a product whose live price breaks the budget is not recommended, with the reason given.

No match means no match

When nothing is relevant enough the answer is “not found”, with the closest items listed as non-matches rather than passed off as recommendations. Brand is a hard constraint: other brands are never substituted.

5The MCP server: one server, two tools

The agent never touches the database or the network directly; everything goes through MCP. The client discovers tools and their JSON schemas with tools/list, then calls them with tools/call. Every call is written to an audit log.

rag.search

Hybrid search over the private catalog.

in : query, top_k, max_price, min_price,
     brand, category, min_rating
out: doc_id, sku, title, price, rating, brand,
     ingredients, recommended_age, relevance, ...

doc_id is the citation id; relevance tells the agent whether to trust the hit.

web.search

Wraps a legitimate search API (Brave, Serper or Tavily); used only for current price or availability. Verified end to end on the live Tavily API; tests and scored runs use canned results so they are repeatable.

in : query, max_results
out: title, url, snippet, price?, availability?,
     source_domain, suspicious

TTL cache (180 s), per-minute rate limit, domain allow/block lists; instruction-like text in snippets is removed and the result flagged suspicious.

Transports: stdio (default; the agent spawns the server as a subprocess) or streamable HTTP. Log: logs/mcp_tool_calls.jsonl with timestamp, arguments, result ids or URLs, cache hit and latency.

6Safety: where a bad answer is stopped

Seven layers from the outside in. None of them depends on the model simply obeying.

Input guardrail (regex, before any model call)Mixing cleaners, harming people or animals: refused with fixed wording and a safety note; no tools called.
Router safety flagTells an attack on the assistant from a normal request that quotes suspicious text: the first is refused, the second is answered with a statement that the quote was not followed.
Tool allow-list and argument enforcementOnly the two tools; at most 6 calls per turn; budget and other hard constraints are re-applied in code.
Tool output is data, not instructionsInstruction-like content in catalog and web text is stripped; suspicious results are never matched or cited.
Evidence-only factsProduct fields are copied from evidence by doc_id; the model cannot write a price or a product that does not exist.
Critic: rules plus LLMRules check budget, citations, prices outside evidence, invented ratings and unsupported claims; the LLM checks support and completeness. A failing draft goes back once, then is rebuilt from evidence only.
Redaction of output and logsKeys live only in .env; every output and log line passes a redactor.

8The data, honestly

The assigned dataset is the Amazon Product Dataset 2020 (Kaggle, 10,002 rows). It differs from the brief's example, and the system keeps every field while leaving a value empty where the data has none, rather than inventing one.

FieldIn the raw dataWhat the system does
title, category, price, featurespresentcleaned; price ranges keep both ends
brandempty columnabout 9% recovered from the manufacturer in the specification text; the rest inferred from the title and labelled as inferred
rating, reviewsnot presentshown as n/a; the assistant says the catalog has no ratings and never states one
ingredientsempty columnmaterial keywords found in the text (wooden, bpa-free, …)
SKUempty columnASIN parsed from the product URL
recommended age (extra)inside the specification textpresent for 5,899 products (62%), e.g. “36 months - 5 years”; the only basis for age statements
category mix67% toys and games; almost no household cleaningthe brief's “stainless-steel cleaner” example returns “no match”

Swap the model in .env only

LLM_PROVIDER=anthropic   LLM_MODEL=claude-haiku-5-5
LLM_PROVIDER=openai      LLM_MODEL=gpt-4.1-mini
LLM_PROVIDER=ollama      LLM_MODEL=qwen3:14b
LLM_PROVIDER=rules       # no model: rule-based fallbacks

ASR, TTS, embeddings and web search are switched the same way.
